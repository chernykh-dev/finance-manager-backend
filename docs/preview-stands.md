# Стенды для PR

Отдельный стенд для конкретного PR по адресу `http://fmb-<номер PR>.yourflow.pro` (Swagger — `/swagger`).
У каждого стенда свои приложение, PostgreSQL и Redis; основной сервер `yourflow.pro` они не трогают.

## Как пользоваться

| Действие | Как |
|---|---|
| Поднять стенд | Повесить на PR метку `preview` |
| Обновить стенд | Запушить в PR — стенд пересобирается сам, данные сохраняются |
| Стенд с копией основной базы | Повесить метку `db-copy` вместе с `preview`. Если стенд уже работает — его база пересоздаётся из копии |
| Удалить стенд | Снять метку `preview` или закрыть / вмержить PR — стенд удаляется вместе с данными |
| Поднять / пересоздать вручную | Actions → **Preview stand** → Run workflow → номер PR; галочки `db_copy` (пересоздать базу копией) и `reset` (пересоздать пустую) |

Ссылка на стенд и его состояние — в комментарии бота в PR (один комментарий, обновляется).

**Данные.** По умолчанию база пустая: справочники (валюты, категории) создаются при старте, пользователей
регистрируйте на стенде. С `db-copy` база — копия основной на момент создания стенда; миграции PR
применяются поверх неё при старте приложения.

> ⚠️ С `db-copy` на стенде оказываются реальные данные пользователей, а стенд открыт по HTTP без
> дополнительной защиты. Используйте только когда это действительно нужно и не держите такой стенд дольше необходимого.

## Сколько стендов выдерживает сервер

Сервер: 2 vCPU · 4 GB RAM · 40 GB SSD. Образы собираются в GitHub Actions, сервер только запускает контейнеры.

| | Лимит памяти | Обычно |
|---|---|---|
| Основной сервер (app + PostgreSQL + Redis + nginx) + ОС | — | ~1 GB |
| Один стенд: app 384 MB, PostgreSQL 256 MB, Redis 64 MB | 704 MB | ~350 MB |

Одновременно работает **не больше 3 стендов** (`MAX_STANDS` в `docker/preview.sh`): даже при упоре всех
стендов в лимиты остаётся запас ~1 GB. Четвёртый стенд не поднимется — бот напишет об ошибке в PR;
снимите `preview` с ненужного PR. Обновление уже работающего стенда в лимит не упирается.

## Как устроено

- `.github/workflows/preview.yml` — реагирует на метки / пуши / закрытие PR и на ручной запуск, собирает образ
  `ghcr.io/chernykh-dev/fmb-api:pr-<N>`, копирует на сервер `docker/docker-compose.preview.yaml` и
  `docker/preview.sh` (в `/var/www/fmb/preview`) и запускает скрипт по SSH (те же секреты, что у деплоя).
- `docker/preview.sh up|down <N>` — поднимает / удаляет compose-проект `fmb-pr-<N>`, проверяет лимит,
  копирует основную базу (`pg_dump` из контейнера `fmb-db`) только в свежую базу стенда.
- Основной nginx (`nginx/nginx.conf`) направляет `fmb-<N>.yourflow.pro` в контейнер `fmb-pr-<N>-app`
  через общую docker-сеть `fmb-preview`; для неподнятого стенда отвечает 404 с подсказкой.
- DNS: wildcard-запись `*.yourflow.pro` → IP сервера.

## Ограничения

- Только PR из этого репозитория: PR из форков не получают секретов, стенды для них не поднимаются.
- Только HTTP, как и основной сервер.
- Образы `fmb-api:pr-<N>` остаются в GHCR после удаления стенда (на сервере удаляются); чистить вручную при необходимости.

## Ручное обслуживание на сервере

```bash
cd /var/www/fmb/preview
docker ps --filter name=fmb-pr-             # какие стенды запущены
bash preview.sh down 34                     # удалить стенд PR #34
docker compose -p fmb-pr-34 -f docker-compose.preview.yaml logs app   # логи приложения стенда
```
